## Verified OK

- **Order-context TTL (A-09).** Expiry is enforced at read: `getOrderContextSummary` filters `status='active' AND expiresAt > now` (`src/lib/order-context.ts:116-128`); every add refreshes the TTL (`:96`, `:111`); expired active rows are swept to `ordered` before merging (`:39-51`). Item snapshot (`productName`, `sizeLabel`, `techniqueName`) is stored, no prices persist (`schema.ts:1141-1162`), and the draft re-quotes via `quoteOrder()`.
- **Cart scoping.** Every read/write is keyed by `conversationId` derived server-side (`sales-tools.ts` `resolveConversationCustomer`, `order-context.ts:141-187`); the model cannot bind the cart to another customer.
- **`draftOrderFromCart` line mapping.** `quoteOrder` pushes exactly one result line per input line in order (`src/lib/pricing.ts:116-124`, `:299-320`), so `resolvedLines[i]` / `insertedLines[i]` alignment is safe even for bundle products.
- **Cash expected-vs-actual math.** Integer cents throughout (`toCents`), cancelled payments excluded, `efectivo` isolated by the deterministic enum, manual movements applied as `in`/`out`, formula `opening + cash + in − out` (`src/lib/cash/session.ts:172-209`). Correct.
- **Closed-session immutability (single-threaded).** No update/delete path exists for closed sessions except `closeSession`, which is guarded by `WHERE id = ? AND status='open'` and returns an error if zero rows were touched (`session.ts:235-252`). The atomic claim itself is sound; only the open side is unguarded (finding above).
- **Migration 0022 ↔ schema.** Enums (`cash_session_status`), columns, defaults, `numeric(12,2)`, and indexes match `src/db/schema.ts:1193-1229`; `cash_movements.direction` has a `CHECK (direction IN ('in','out'))`. Journal includes migrations 0020-0023 (`src/db/migrations/meta/_journal.json`). The only gap is the missing partial unique index on the open session.
- **Broadcast opt-out (A-10).** Opted-out contacts are excluded **before** the dry-run count (`tools-broadcast.ts:116-127`), so the preview equals the send set; segments `new_leads` / `qualified` / `no_org` / `with_orders` / `search` filter correctly against `contacts` / `orders`, with `%_\` escaped in the search term (`:87`). The `dryRun → CONFIRM` two-step flow and per-recipient canonical persistence are intact; bulk sends are stamped `agent` (not `operator`) so they don't mute the agent (`:169-177`).
- **Link-preview SSRF (B-08).** Strong implementation: every DNS answer validated before connect, connection pinned to the validated address via a custom `lookup` (closes the rebind window), private ranges for IPv4 (RFC1918, loopback, link-local, CGNAT, multicast) and IPv6 (`::`, `::1`, fe80::/10, fc00::/7, ff00::/8, IPv4-mapped) blocked, private hostnames blocked, redirects refused, `content-length` + streamed size cap at 256 KB, 5 s timeout, authenticated, and rate-limited in its own bucket (`src/app/api/link-preview/route.ts:1-190`, `helpers.ts`). Only OG/title metadata is returned.
- **Public products feed (B-10).** Anonymous callers get active rows only; `basePrice` is forced to `null`, no cost/BOM/recipe fields, `?all=1` requires a session, response capped at 200, rate-limited (`src/app/api/products/route.ts:1-60`).
- **Public promotions feed (A-14).** Anonymous callers get active rows only; exposes marketing fields + admin-configured `customPrice` + component names/availability, no internals; capped and rate-limited. Numeric `customPrice` is a string from the driver, so the `customPrice ? Number(...) : null` guard correctly preserves a legitimate `0.00`.
- **`/api/setup` (B-11).** Never exposes secrets — only `needsSetup`, `hasAdminUser`, `seeded`. Unauthenticated only while no admin exists (the bootstrap question), then admin-only; rate-limited (`src/app/api/setup/route.ts:1-55`).
- **Business tools (A-11).** `getBusinessHours`, `checkAvailability`, `getPaymentAlias` read only the `settings` table and say "not configured" instead of inventing values (`sales-tools.ts:1604-1720`). `taller_horarios` shape written by `src/app/actions/settings.ts` matches `BusinessHourDay[]`, and payment data (`taller_alias/cbu/banco`) is not leaked by the public `/api/business` (`src/lib/business.ts`), which reads only `business.*` keys.
- **Prompt surface (W9).** Sales prompt carries product/técnica/promo **names only**, never prices, and directs all quotes to the pricing engine (`prompt-builder.ts:25-49`; `sales-agent.ts:151-177`).
- **No food-domain leftovers found** in the reviewed W9 paths: cart is a pre-draft textile order cart, promos are named bundles, cash covers pickup payments. Comments describe the domain correctly.

## Notes / non-findings

- `getSnapshot` counts **all** manual movements of the session without a time filter — correct by construction because movements are scoped to `sessionId` and closed sessions accept none.
- `pendingBalances()` in `tools-cash.ts:77-93` issues one payments query per open order (N+1). Performance only; no correctness impact.
- `order_context_items` rows are made inert, never deleted — matches the documented design ("swept to ordered"), but the table grows without a retention job.
- `promotionalPrice` surfaced by `getPromotions` carries no explicit "total vs per-unit" qualifier; the prompt forbids extrapolation, so this is a copy-clarity risk, not a pricing bug.
